Source contract audit against private AROS master bfdbbd7c and generated SDK headers, 2026-11-18. Chromium condition_variable_posix constructor excluded AROS from pthread_condattr_setclock(CLOCK_MONOTONIC), using NULL attributes. Current AROS pthread_cond_init defaults to CLOCK_REALTIME; timedwait interprets absolute deadline using cond_clock. Chromium TimedWait computes deadline with CLOCK_MONOTONIC. AROS clock_gettime MONOTONIC uses GetUpTime. Therefore constructor and wait used different time domains. Remove obsolete AROS exclusion, enabling existing monotonic-attribute path. Both generated SDK headers declare attr APIs. This is a Chromium-side correction to the existing adapter, not a direct-native synchronization migration, SDK change, or explanation of deferred ARM stalls.
