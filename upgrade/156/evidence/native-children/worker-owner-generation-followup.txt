CommandLine registry worker bindings remain raw CommandLine pointers. FindCommandLineForTask validates pointer equality against live owner entries, then falls through to native parent traversal if no pointer match. A late worker plus recycled CommandLine address can therefore resolve to a new owner; an invalid explicit binding should instead be a terminal retired-owner barrier.
The token must be captured at worker creation, not first execution: ThreadParams currently captures raw CommandLine* in platform_thread_posix.cc:160 and:213, then binds at ThreadFunc:93. Capturing a generation only inside ArosBindCurrentThread is too late if its creator retired before scheduling. Normal ThreadFunc unbinds after TerminateOnThread, but safe cleanup should not depend on absent abnormal/late workers.
A bounded future design is an opaque logical owner token captured at CreateThread, with identity validation on binding and lookup, and invalid binding returning null without parent fallback. Keep bootstrap identity0 handling separate. This can use the narrow base/aros/process_local.h interface instead of altering the widely included CommandLine header. Requires native tests for delayed start, retirement, address reuse, valid child worker inheritance and ordinary teardown. No generation patch in current diagnostics candidate.
